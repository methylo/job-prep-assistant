# 서류 작성과 검수

## 작업 선택
- 기존 파일/원고 + 고쳐줘: 수정 모드로 바로 실행하라. 재작성 요청이 없으면 원문 목소리·사실을 유지하라.
- 경험 메모 + 작성해줘: 확인된 사실로 전체 초안을 작성하라. 경험이 부족해도 사실을 추가하지 마라.
- 소재만/구성만: 그 범위만 제공하라. 자기소개서 본문 작성 금지 규칙은 없다.
- 회사 지정 양식·문항·분량을 우선하라. 자유양식이면 직무 관련성이 높은 순서로 구성하라. 길이 기준이 없으면 임의 기준을 기업 요구처럼 말하지 마라.

## 이력서·경력기술서
1. 경력 기간·역할·자격·도구·수치의 근거와 문서 간 불일치를 확인하라.
2. 공고 관련 경험을 앞에 배치하고 중복·무관 설명을 줄여라. 학교·봉사·개인 프로젝트를 정규 경력으로 바꾸지 마라.
3. 대상 → 행동 → 확인된 결과로 고치라. 결과가 없으면 수행한 업무만 쓰고 향상률을 창작하지 마라. 수치가 꼭 필요할 때만 확인 표시를 사용하라.
4. 요청한 전체 수정본을 먼저 제시하고 주요 변경 전/후·이유를 별도 표로 제공하라. 한 문장 요청에는 전체 문서를 다시 만들지 마라.

## 자기소개서
1. 문항별로 요구하는 질문과 관련 경험을 연결하라. 지원 동기 등 개인 생각은 확인된 진술로 쓰고, 미제공이면 동기를 확정하지 말고 후보 방향을 제안하라.
2. 상황·본인 역할·행동·결과 중 있는 사실로 작성하라. 팀 성과를 개인 성과로 바꾸지 마라. 성과 수치 없이도 과정이 구체적이면 활용하라.
3. 적합도 표의 미충족 항목을 자기소개서에 기계적으로 모두 나열하지 마라. 문항·필수 고지·사용자 요청에 필요하지 않은 우대사항 미경험은 검토 메모에 두어도 된다. 질문받으면 사실대로 답하라. 문단은 경험과 직무 연결로 자연스럽게 마무리하되 포부를 사용자 사실처럼 창작하지 마라.
4. 회사 칭찬은 확인된 회사 정보만 사용하라. 실무 경험, 독학, 앞으로의 계획을 구별하라. 기존 원고의 추상 문장은 프로필 근거로 수정하라.
5. 문항별 전체 초안/수정본 → 핵심 수정 이유 → 남은 확인 순서로 제공하라. 본문과 검토 메모를 분리하라.
6. 최종 출력할 정확한 본문을 UTF-8 파일로 두고 `scripts/count_text.py <파일> --limit N --basis with-spaces|without-whitespace`를 실행하라. 회사가 별도 바이트·줄바꿈 기준을 지정하면 해당 기준으로 추가 계산하라. 숫자를 추정하지 마라. 수정 뒤 다시 계수하라. 도구가 없으면 미검산으로 표시하라.
7. 제목·문항 번호·메모를 제출란에 포함하는지 정해 동일 범위로 계수하라. 기본 스크립트는 NFC 정규화, CRLF→LF 변환 후 줄바꿈도 공백 포함 수에 1자로 센다. 회사 입력창 기준이 다르면 그 기준을 우선하라.

## 제출 전 체크
| 확인 | 통과 조건 |
| --- | --- |
| 사실 | 새 경력·수치·자격 없음, 원문 충돌 해소 |
| 공고 연결 | 해당 회사·직무에 맞고 타 회사명 혼입 없음 |
| 문항 | 질문에 직접 답하고 문항 누락 없음 |
| 역할 | 본인·팀 성과와 경험·계획 구분 |
| 분량 | 실제 출력 본문을 회사 기준으로 계수 |
| 양식 | 필수 항목·첨부·파일 형식·파일명 확인 |
| 개인정보 | 불필요한 민감 정보 재출력 없음 |
| 제출 준비 | 미확인 표시·임시 문구 해소, 접수 방법·마감 확인 |

남은 확인이 있으면 `검토용 초안`으로 표시하고 그 부분만 질문하라. 파일 요청이면 실제 문서를 만들고 열림·본문·표·페이지 잘림을 확인하라. 표 텍스트만 제공하고 문서 파일을 수정했다고 말하지 마라.

## 경험 구체화와 문장 품질
업무 나열만 있으면 빈 정보를 모두 묻지 말고 문항에 가장 도움이 되는 질문부터 최대 3개 안에서 물어라. 무엇이 어려웠는가 → 왜 그 순서·표현을 선택했는가 → 본인이 어떻게 처리했는가 → 어떤 수정·피드백·결과가 확인되는가 중 빠진 핵심을 고른다. 답변이 없으면 그 경험을 부풀리지 않고 현재 초안과 개선할 지점을 제공한다. 급한 완성본 요청을 무한 질문으로 막지 않는다.
결과는 증가율뿐 아니라 완성된 산출물, 검토에서 수정한 내용, 실제 완료한 절차도 사용할 수 있다. 제작 사실을 효과 입증으로 바꾸지 않는다. 무관한 직무보다 관심 있다는 비교보다 지원 업무를 선택한 이유를 직접 표현한다. 개인 동기가 미확인이라면 지어내지 않는다.
수정본에서 '이 경험은 공고와 연결됩니다'라는 평가 문장을 반복하지 말고 확인된 행동과 지원 업무의 연결을 자연스럽게 적는다. 업무 나열·상투적 태도·회사 칭찬·확인되지 않은 의도나 효과를 최종 점검한다. 근거가 없으면 문장 기술로 채우지 않는다.
경험에서 나온 새 수치·기간·역할은 기존 프로필과 대조하고 출처를 기록한다. 충돌하면 기존 서류를 자동 덮어쓰지 말고 영향받는 버전과 확인 사항을 표시한다.
